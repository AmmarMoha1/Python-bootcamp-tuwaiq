# Week 10 - Django Migrations Lab

## Project Overview

This project demonstrates how to safely evolve a Django database schema using migrations.

The lab focuses on modifying a `Product` model while preserving existing data.

The main tasks include:

- Creating a Django project and `catalog` app
- Creating a `Product` model
- Adding a new `code` field
- Creating named migrations
- Inspecting migration status and plans
- Creating a data migration
- Populating existing records
- Making the `code` field required and unique
- Renaming `stock` to `quantity`
- Verifying the migrated data
- Testing migration rollback

# Schema Evolution

## Step 1 - Add the `code` Field

The `code` field was first added with `null=True`.

```python
code = models.CharField(
    max_length=30,
    null=True,
)
```

Using `null=True` allows existing database rows to remain valid because they do not yet have a value for `code`.

---

## Step 2 - Create a Named Migration

```bash
python manage.py makemigrations catalog --name add_product_code
```

This creates a migration similar to:

```text
0002_add_product_code.py
```

The migration contains an `AddField` operation.

---

## Step 3 - Inspect the Migration

Check the migration status:

```bash
python manage.py showmigrations catalog
```

Preview the migration plan:

```bash
python manage.py migrate --plan
```

Inspect the SQL generated by Django:

```bash
python manage.py sqlmigrate catalog 0002
```

These commands allow the migration to be reviewed before it is applied.

---

## Step 4 - Create a Data Migration

An empty migration was created:

```bash
python manage.py makemigrations catalog --empty --name populate_product_code
```

This creates a migration similar to:

```text
0003_populate_product_code.py
```

---

## Step 5 - Populate Existing Product Codes

The data migration fills the new `code` field using each product's primary key.

```python
from django.db import migrations


def populate_product_code(apps, schema_editor):
    Product = apps.get_model("catalog", "Product")

    for product in Product.objects.all():
        product.code = str(product.pk)
        product.save(update_fields=["code"])


def clear_product_code(apps, schema_editor):
    Product = apps.get_model("catalog", "Product")

    Product.objects.update(code=None)


class Migration(migrations.Migration):

    dependencies = [
        ("catalog", "0002_add_product_code"),
    ]

    operations = [
        migrations.RunPython(
            populate_product_code,
            clear_product_code,
        ),
    ]
```

After this migration, the data becomes similar to:

```text
id   name      code
1    Laptop    1
2    Phone     2
3    Mouse     3
```

The migration uses:

```python
apps.get_model()
```

instead of importing the current model directly because migrations should use the historical version of the model.

---

## Step 6 - Make `code` Required and Unique

After all existing products have a value, the field can safely be changed to:

```python
code = models.CharField(
    max_length=30,
    unique=True,
)
```

Create the migration:

```bash
python manage.py makemigrations catalog --name require_unique_product_code
```

This migration uses `AlterField`.

The safe migration strategy is:

```text
Expand
   ↓
Backfill
   ↓
Enforce
```

This means:

1. Add the field as nullable
2. Populate existing data
3. Make the field required and unique

---

## Step 7 - Rename `stock` to `quantity`

The model field was changed from:

```python
stock = models.IntegerField()
```

to:

```python
quantity = models.IntegerField()
```

Create the migration:

```bash
python manage.py makemigrations catalog --name rename_stock_quantity
```

When Django asks:

```text
Was product.stock renamed to product.quantity? [y/N]
```

Select:

```text
y
```

Django creates a `RenameField` operation, which preserves the existing stock values.

## Final Product Model

```python
from django.db import models


class Product(models.Model):
    name = models.CharField(max_length=100)

    code = models.CharField(
        max_length=30,
        unique=True,
    )

    quantity = models.IntegerField()

    def __str__(self):
        return self.name
```

The final database structure is:

```text
Product
-------------------------
id          Primary Key
name
code        Unique / Not Null
quantity
```

## Rollback Test

To rollback the rename migration:

```bash
python manage.py migrate catalog 0004
```

This reverses:

```text
quantity → stock
```

To apply the latest migration again:

```bash
python manage.py migrate catalog
```

This restores:

```text
stock → quantity
```

## Migration Mental Model

Django migrations can be understood using three different states:

```text
models.py
"What the application wants"

        ↓ makemigrations

Migration Files
"How the schema should change"

        ↓ migrate

Database Schema
"What is actually applied"
```

`makemigrations` creates migration instructions.

`migrate` applies those instructions to the actual database.

## Conclusion

This lab demonstrates how Django migrations can safely change a database schema without losing existing data.

The most important migration pattern used in this project is:

```text
Add nullable field
        ↓
Populate existing data
        ↓
Make field required
        ↓
Apply constraints
```

This approach helps prevent migration failures and protects existing database records.
